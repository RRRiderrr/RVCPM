# Rider's Vencord custom plugin manager (RVCPM) v0.1.1

RVCPM — менеджер кастомных **Vencord userplugins** для Windows. Интерфейс написан на WinForms .NET Framework 4.7.2 и отображается через WebView2 в Discord-подобном оформлении.

## Что уже реализовано

- Установка сразу нескольких плагинов из:
  - `.ts` / `.tsx` файлов;
  - папок плагинов;
  - ZIP-архивов;
  - GitHub-репозитория, `/tree/...` пути или прямой `/blob/...` ссылки.
- Drag & Drop файлов и папок прямо в окно RVCPM. Для браузерного drop используется безопасный снимок файлов; для больших пакетов (>16 МБ) используйте нативные кнопки **Files / Folder**.
- Своя библиотека плагинов и конфигурация каждого ПК в `%LOCALAPPDATA%\RVCPM`.
- RVCPM держит **свою управляемую копию исходников Vencord**, поэтому не трогает пользовательский checkout Vencord.
- При установке нового плагина всегда подтягивается свежий `origin/main` Vencord, затем выполняются зависимости, сборка и injection.
- Git и Node.js проверяются автоматически; при отсутствии RVCPM пытается поставить/обновить их через `winget`.
- Версия `pnpm` не захардкожена: читается из актуального `package.json` Vencord и запускается через `npx pnpm@<version>`.
- Включение/выключение плагинов из RVCPM.
- Если Discord запущен, изменение enabled-state **не правит settings.json на лету**: изменение ставится в очередь, появляется баннер «нужен перезапуск», а запись применяется после остановки Discord. Есть кнопка перезапуска Discord.
- Редактирование стандартных настроек Vencord-плагина прямо из RVCPM: `STRING`, `NUMBER`, `BOOLEAN`, `SELECT`, `SLIDER`, а также простые `CUSTOM` значения, которые можно безопасно распознать статически.
- `COMPONENT`, сложный `CUSTOM` и `BIGINT` не исполняются в менеджере: произвольный React-код настройки остаётся доступен в самом Discord. Это сделано намеренно, чтобы RVCPM не выполнял UI-код неизвестного плагина вне Vencord.
- Удаление плагина с опцией удалить его сохранённые настройки Vencord.
- Просмотр описания плагина; для GitHub отображаются описание репозитория и README.
- Проверка обновлений:
  - GitHub: сравнение **установленного commit конкретного плагина** с удалённым commit, затем `fetch/reset` выбранной ветки;
  - локальный файл/папка: SHA-256 сравнение с исходным путём;
  - ZIP и Drag & Drop являются снимками и автоматически не обновляются — более новую версию нужно импортировать снова. Если имя Vencord-плагина совпадает, RVCPM распознаёт это как замену, а не создаёт дубликат.
- GitHub-плагины после установки тоже получают собственный immutable-снимок в `packages`: простая проверка/анализ GitHub не может незаметно изменить следующую сборку.
- Обновление одного плагина или всех сразу с одной итоговой пересборкой Vencord; при ошибке сборки/инжекта пакет и метаданные откатываются на предыдущую установленную версию.
- Логи всех операций и отмена выполняющейся операции.
- Discord Stable / PTB / Canary / Auto и собственный путь установки.
- RU / UA / EN интерфейс; новая установка стартует на английском.
- **Plugins+**: когда RVCPM управляет хотя бы одним плагином, он добавляет внутренний скрытый `RVCPMIntegration` userplugin. Он меняет заголовок стандартного пункта Vencord Settings `Plugins` на `Plugins+`, не редактируя core-файлы Vencord вручную. При отсутствии управляемых плагинов интеграция не добавляется.
- Безопасное извлечение ZIP: защита от `../` path traversal, лимит 2000 файлов и 128 МБ распакованного содержимого.
- Атомарное сохранение конфигов и backup Vencord `settings.json` перед изменением; неудачная установка/удаление откатывает staged-настройки.
- Временные файлы старше двух дней автоматически очищаются при старте; неиспользуемые GitHub-cache удаляются на следующем запуске.

## Какие форматы реально поддерживает Vencord

По актуальной структуре Vencord userplugin имеет одну из двух официально документированных точек входа:

```text
src/userplugins/myPlugin.ts
src/userplugins/myPlugin.tsx
```

или:

```text
src/userplugins/myPlugin/index.ts
src/userplugins/myPlugin/index.tsx
```

Папка может содержать дополнительные файлы: `native.ts`, `.ts/.tsx` компоненты, CSS, JSON и другие импортируемые ресурсы. `native.ts` — специальный Node/Electron entry point; это **не отдельный устанавливаемый плагин**.

RVCPM принимает ZIP и GitHub URL как транспорт/источник, но перед сборкой нормализует каждый пакет в корректную структуру `src/userplugins`.

Также учитываются target suffixes Vencord: `.dev`, `.web`, `.browser`, `.desktop`, `.discordDesktop`, `.vesktop`. Web/Vesktop-only пакет не устанавливается как обычный Discord Desktop plugin. `.dev.ts(x)` требует включить Dev Build.

## Хранилище RVCPM

```text
%LOCALAPPDATA%\RVCPM\
├─ config\config.json
├─ packages\                 # установленные snapshots всех плагинов, включая GitHub
├─ repositories\             # GitHub checkout'ы только для анализа/обновлений
├─ vencord\                  # отдельный checkout Vencord
├─ logs\rvcpm.log
├─ temp\
└─ WebView2\                 # профиль интерфейса RVCPM
```

Настройки самого Vencord читаются/изменяются в стандартном Windows-пути Vencord:

```text
%APPDATA%\Vencord\settings\settings.json
```

Если Discord работает, RVCPM не пишет туда напрямую: pending-изменения сначала лежат в собственном `config.json`.

## Сборка проекта

Требуется Windows 10/11 и Visual Studio 2022 или Build Tools с workload **.NET desktop development** и .NET Framework 4.7.2 Targeting Pack.

Самый простой способ:

```text
Build_Release.bat
```

Скрипт найдёт MSBuild через `vswhere`, выполнит NuGet restore и Release build, а затем сформирует:

```text
dist\RVCPM\
```

Можно также открыть `RVCPM.sln` в Visual Studio и собрать `Release | Any CPU`.

NuGet-зависимости:

- `Microsoft.Web.WebView2 1.0.4129.50`
- `Newtonsoft.Json 13.0.3`

На Windows 11 WebView2 Runtime обычно уже присутствует. Если его нет/он повреждён, приложение покажет понятное сообщение при старте.

## Важное про безопасность

Custom Vencord plugin — это код, который выполняется внутри Discord. RVCPM проверяет структуру пакета, безопасно работает с ZIP и не запускает плагин при анализе, но **не может сделать неизвестный плагин безопасным**. Устанавливайте код только из доверенных источников.

## Ограничения v0.1.1

- RVCPM не пытается исполнять произвольный `settingsAboutComponent`/`OptionType.COMPONENT` в собственном WebView2. Такие настройки открывайте в Discord.
- GitHub `/tree/branch/path` с веткой, содержащей `/`, неоднозначен в URL. Для таких репозиториев проще вставить ссылку на корень проекта.
- GitHub private repositories пока не поддерживают авторизацию; публичные репозитории работают без токена.
- ZIP/Drag & Drop snapshot не имеет гарантированного upstream, поэтому автообновление для него отключено.

## Статус сборки этого архива

Исходники подготовлены под .NET Framework 4.7.2. В среде, где этот архив был сформирован, отсутствует Windows MSBuild/.NET Framework toolchain, поэтому здесь выполнена статическая проверка структуры и JavaScript (`node --check`), но Windows EXE не был скомпилирован. На Windows `Build_Release.bat` выполняет restore + полноценную сборку.
